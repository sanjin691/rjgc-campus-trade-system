# 校园二手商品交易系统

> 软件工程课程项目 · 版本 v1.7.0 · 2026-11
> 技术栈：Python 3.10+、SQLite、Pillow、原生 HTML/CSS/JavaScript

本仓库实现用户管理与商品管理：用户模块负责账号、认证、资料维护及管控；
商品模块负责创建、本人列表、修改及删除。交易管理只保留入口，未实现交易或支付。
个人分工：熊梓钊负责商品功能及对应需求、架构、测试与变更追溯；用户管理由队友提供。
商品细节见 [GOODS.md](GOODS.md)。公共布局可调整，个人信息区的内容、控件样式和逻辑不改动。

## 功能一览

| 模块 | 功能 | 使用者 | 状态 |
| --- | --- | --- | --- |
| 注册 | 填写学号/工号、姓名、校园邮箱等信息注册账号，完成格式与唯一性校验 | 访客 | ✅ |
| 登录 | 学号/工号或邮箱 + 密码登录；连续失败限流 | 全部用户 | ✅ |
| 退出 | 主动退出，销毁当前会话 | 全部用户 | ✅ |
| 个人信息 | 查看本人资料；修改姓名、邮箱、手机号、学院、专业 | 普通师生用户 | ✅ |
| 账号安全 | 修改本人密码（需校验当前密码，改后其他设备下线） | 全部用户 | ✅ |
| 用户管理 | 查看全部用户列表 | 管理员 | ✅ |
| 用户管理 | 编辑任意用户资料，并可更正学号/工号 | 管理员 | ✅ |
| 用户管理 | 重置指定用户密码（忘记密码的兜底手段） | 管理员 | ✅ |
| 用户管理 | 删除账号（不可删自己、不可删最后一名管理员） | 管理员 | ✅ |
| 用户管理 | 在后台新增管理员账号 | 管理员 | ✅ |
| 商品管理 | 创建、查看本人商品、修改（二次确认）、删除（二次确认） | 登录后的发布者 | 已实现 |
| 交易管理 | 申请/接受/查询交易 | — | 🚧 占位，返回 501 |

系统分两种身份：

- **普通师生用户**（学生与教职工）：只能查看和修改自己的信息，可修改本人密码。
- **管理员**：在普通用户能力之外，可查看所有用户、编辑任意资料、重置密码、删除账号、新增管理员。

## 快速开始

### 环境要求

| 项目 | 要求 |
| --- | --- |
| Python | 3.10 或更高版本；先安装 `requirements.txt` 中的 Pillow |
| Node.js | 仅运行前端交互测试时需要，浏览器使用不需要Node |
| 操作系统 | Windows 10/11、Linux、macOS 均可 |
| 浏览器 | Chrome / Edge / Firefox 最近两个版本 |

### 启动

先在项目目录安装依赖，然后可双击 `start.bat`，或手动启动：

```powershell
python -m pip install -r requirements.txt
python app.py
```

浏览器打开 **http://127.0.0.1:8000**。首次启动会自动创建 `data/user_management.db`
与默认管理员账号。

### 默认管理员

| 角色 | 学号 / 工号 | 密码 |
| --- | --- | --- |
| 管理员 | `ADMIN001` | `Admin@123` |

> 该账号仅用于课程演示。首次登录后请立即在「个人信息 → 修改密码」中更换，
> 或由管理员删除后新建一个管理员账号。

普通师生用户请点击「注册」自行创建；管理员可在后台再新增管理员账号。

### 可选启动参数

```bash
python app.py --port 8080      # 更换端口
python app.py --open           # 启动后自动打开浏览器
python app.py --db data/my.db  # 指定数据库文件
```

## 操作手册

### 普通师生用户

1. **注册**：在登录页切到「注册」，填写学号/工号、姓名、校园邮箱、密码与确认密码
   （手机号、学院、专业选填）→ 提交。字段不合法时会逐字段提示。
2. **登录**：输入学号/工号或邮箱 + 密码 → 进入「个人信息」。
3. **维护资料**：修改姓名、邮箱、手机号、学院、专业 → 「保存修改」，保存后立即生效。
   学号/工号是账号标识，个人不能修改；修改邮箱时会校验是否已被他人占用。
4. **修改密码**：在「修改密码」面板输入当前密码与新密码 → 保存。
   修改成功后当前设备保持登录，其他设备上的登录全部失效。
5. **退出**：点击右上角「退出登录」。
6. **忘记密码**：系统不提供自助找回，请联系管理员重置。

### 管理员

1. 用管理员账号登录 → 默认进入「用户管理」。
2. **查看**：列表展示全部用户的学号/工号、姓名、邮箱、手机号、学院、专业、角色与注册时间。
3. **编辑**：点击某用户的「编辑」，修改资料；学号/工号也可更正（校验格式与唯一性，
   改完后旧学号/工号立即无法登录）。角色不可修改。
4. **重置密码**：点击「重置密码」→ 输入新密码 → 该用户所有登录状态立即失效，
   需用新密码重新登录。
5. **删除账号**：点击「删除」→ 二次确认。不能删除当前登录的账号，也不能删掉最后一名管理员。
6. **新增管理员**：点击右上角「新增管理员账号」→ 填写学号/工号、姓名、校园邮箱与初始密码 →
   创建后即可用该账号登录后台。
7. **商品入口**：可管理本人商品；管理员身份不额外赋予修改或删除他人商品的权限。交易入口仍为占位。

### 商品管理（熊梓钊负责）

1. **创建**：点击“创建商品”，填写名称、分类、价格、成色和描述，可选图片。成功后关闭表单；继续创建需重新点击入口。
2. **查看**：点击“我的商品”读取本人列表，展示名称、价格、分类、成色、图片及发布时间。
3. **修改**：从卡片进入编辑，可保留、移除或增加图片。点击保存后须再次确认；取消不发请求，输入保留，确认后保存成功返回列表。创建不增加此确认。
4. **删除**：二次确认并提示不可恢复；只允许本人删除，商品及关联图片在同一事务内清理，成功后刷新列表。
5. **异常**：明确校验失败不部分保存；10秒未响应或网络结果不明时提示结果未知，不把超时当作失败，不自动重试。当前页保留输入，提供新页面登录或查询入口。

名称1～50字符、描述1～500字符；价格0.01～99999.99元，最多两位小数，以整数分保存。
分类及成色使用预设选项；最终图片0～3张，单张不超过2 MiB、2000万像素。
前端预检数量/大小/扩展名，后端严格检查Base64、实际格式和完整解码，拒绝伪装、损坏及超限文件。

### 可读性与班级公约

`shell.css`只调整公共页眉、导航、页脚和商品区域：放大字体，主要操作保持至少44px高度，
增加键盘焦点和选中态，窄屏导航及商品表单重排。不调整全局body字号，不选择个人信息区。
顶部采用等宽分段导航，普通用户三个入口、管理员四个入口自动均分；白底选中卡片与短下划线共同标识当前位置。
这些是为第七条基础适配采取的措施，不代表通过完整无障碍认证或特殊用户测试。
浏览器可用Ctrl加加号放大；交付检查应覆盖390px手机宽度及200%缩放。
修改和删除都提供确认；确认属于前端交互保护，不替代服务端登录、归属和CSRF检查。

## 系统结构与设计

整个系统按业务划分为三个子系统，前两个已实现：

| 子系统 | 状态 | 代码位置 | 说明 |
| --- | --- | --- | --- |
| 用户管理子系统 | ✅ 已实现 | `app.py` / `database.py` / `validators.py` / `security.py` | 注册、登录、资料与账号管控 |
| 商品管理子系统 | 已实现 | `goods.py` / `goods_validation.py` / `goods_store.py` | 创建、修改、删除、本人查询与图片管理 |
| 交易管理子系统 | 🚧 规划中（空） | `trade.py` | 同上 |

- `GET /api/subsystems` 返回三个子系统的状态与功能；只有交易模块仍为占位。
- 商品采用“页面→请求入口→商品服务→数据访问”的简化分层，字段和图片检查集中在校验工具中。

### 分层

```
浏览器（原生 HTML/CSS/JS）
   │  fetch + X-CSRF-Token
   ▼
HTTP 层      RequestHandler：解析请求、限流、安全响应头
   ▼
应用层      Application.dispatch：路由匹配 → 来源校验 → 内容类型 → JSON 解析 → 鉴权 → 分发
   ▼
业务处理     api_* 函数：校验（validators）→ 加密/令牌（security）→ 读写（database）
   ▼
数据层      UserStore / SessionStore：参数化 SQL、事务、唯一约束；SQLite（WAL）
```

### 关键设计取舍

- **不用 Web 框架**：沿用现有标准库HTTP服务，路由、鉴权、CSRF 显式实现，便于讲解每一层；
  代价是要自己处理分派与错误映射（本项目在 `Application.dispatch` 里集中做了）。
- **SQLite 而不是 MySQL**：单机部署、免安装、事务与唯一约束完备；数据量在千级用户内足够。
  代价是单写入者；更换数据库需要适配用户及商品的数据访问代码并回归验证。
- **会话存库而不是存内存**：服务重启后登录态不丢；令牌只存 SHA-256 摘要。
- **实体与视图分离**：`_public_user()` 统一脱敏，接口不会返回密码哈希。

## 接口说明

### 统一响应格式

成功：

```json
{ "ok": true, "message": "可选提示", "data": { } }
```

失败：

```json
{ "ok": false, "message": "人类可读的错误说明", "errors": { "字段名": "字段级错误" } }
```

POST/PATCH写操作使用 `Content-Type: application/json`，DELETE可无请求体；
商品创建、修改的完整JSON请求体上限9 MiB，其他接口64 KiB，不接受压缩或分块传输；
登录后的写操作需携带 `X-CSRF-Token`（前端已自动处理）。

### 错误码

| 状态码 | 含义 | 典型场景 |
| --- | --- | --- |
| 400 | 请求不合法 | JSON 格式错误、删除当前登录账号 |
| 401 | 未登录 / 会话失效 | 未带 Cookie、会话过期、密码已重置 |
| 403 | 无权限 | 普通用户调用管理接口、CSRF 令牌不匹配 |
| 404 | 资源不存在 | 用户不存在、接口不存在 |
| 409 | 唯一约束冲突 | 并发注册时学号/邮箱重复 |
| 413 | 请求体过大 | 超过对应接口上限 |
| 415 | 内容类型不支持 | 非 `application/json` |
| 422 | 字段校验失败 | 邮箱格式错误、两次密码不一致 |
| 429 | 请求过于频繁 | 登录失败次数超限 |
| 501 | 尚未实现 | 交易子系统占位接口 |
| 500 | 服务器内部错误 | 未捕获异常（服务端打印堆栈） |

### 接口清单

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/api/auth/register` | 公开 | 注册普通师生用户 |
| `POST` | `/api/auth/login` | 公开 | 登录并签发会话 |

## 数据库设计

SQLite，文件位于 `data/user_management.db`（首次启动自动创建，WAL 模式）。

### users

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | INTEGER | PK, AUTOINCREMENT | 代理主键 |
| student_no | TEXT | NOT NULL, UNIQUE, NOCASE | 学号/工号，4–20 位字母数字 |
| name | TEXT | NOT NULL | 姓名，2–20 字符 |
| email | TEXT | NOT NULL, UNIQUE, NOCASE | 邮箱，≤120 字符 |
| phone | TEXT | NOT NULL DEFAULT '' | 手机号，11 位，可空 |
| college | TEXT | NOT NULL DEFAULT '' | 学院，≤30 字符 |
| major | TEXT | NOT NULL DEFAULT '' | 专业，≤40 字符 |
| role | TEXT | CHECK IN ('user','admin') | 角色 |
| password_hash | TEXT | NOT NULL | `pbkdf2_sha256$迭代$盐$摘要` |
| created_at / updated_at | TEXT | NOT NULL | ISO-8601 UTC |

### sessions

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| token_hash | TEXT | PK | 会话令牌的 SHA-256 摘要 |
| user_id | INTEGER | FK → users(id) ON DELETE CASCADE | 所属用户 |
| csrf_token | TEXT | NOT NULL | CSRF 令牌 |
| created_at / expires_at | TEXT | NOT NULL | 创建时间 / 过期时间（24 小时） |

`idx_sessions_user_id` 用于按用户批量删除会话；删除用户时其会话随外键级联删除。

## 安全措施

商品表：`goods`记录发布者、五项商品信息、整数分价格和时间；`goods_images`记录商品外键、顺序、MIME、BLOB及尺寸。
商品与图片使用同一SQLite事务，失败回滚；图片检查通过后再开启保存事务。
商品删除级联清理图片；用户删除也按商品表外键规则清理其商品，不修改原用户管理接口。

- 密码使用 **PBKDF2-HMAC-SHA256**（26 万次迭代、16 字节随机盐）保存，不存明文。
- 会话令牌 32 字节随机、24 小时有效，数据库只存 SHA-256 摘要。
- Cookie 使用 `HttpOnly` + `SameSite=Lax`，正式部署设置 `COOKIE_SECURE=1` 启用 `Secure`。
- 登录后的写操作校验会话对应的 **CSRF 令牌**，并校验 `Origin` 与 `Host` 一致。
- 管理员接口在服务端校验角色，不依赖前端隐藏按钮。
- 登录失败统一提示“账号或密码错误”，并对不存在的账号做一次假哈希比对，防止时序枚举。
- 连续失败 5 次（同 IP + 账号，10 分钟窗口）返回 429。
- 所有数据库查询使用参数绑定；前端不渲染用户输入的 HTML。
- 响应头包含 CSP、`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 等。
- 请求体按接口限额读取，非法JSON拒绝；商品字段白名单和归属检查由服务端执行。

安全边界：本项目为课程实现，未做 HTTPS 终结、WAF、邮件验证与分布式限流；
正式部署应置于反向代理之后并启用 HTTPS。

## 已知限制与后续计划

| 限制 | 影响 | 计划 |
| --- | --- | --- |
| 注册接口无频率限制 | 可被批量注册刷库 | 加验证码或按 IP 限流 |
| 邮箱未做归属验证 | 可能被抢注，也无法自助找回 | 接入校园邮箱验证码 |
| 无自助找回密码 | 依赖管理员重置 | 邮件/短信找回（需 SMTP） |
| 管理员列表无分页与搜索 | 用户量大时页面变慢 | 加 `limit/offset` 与关键词查询 |
| 限流状态存内存 | 服务重启后清零 | 迁移到数据库或 Redis |
| SQLite 单写入者 | 高并发写入可能排队 | 换 MySQL / PostgreSQL |
| 无操作审计日志 | 管理员操作不可追溯 | 增加审计表 |
| 学院/专业为自由文本 | 统计口径不一致 | 改为字典表 |

## 常见问题

**Q：启动时报端口被占用？**
换端口：`python app.py --port 8080`，或先关闭占用 8000 的进程。

**Q：页面还是旧版本？**
强制刷新（Ctrl+F5）；静态资源带 `Cache-Control: no-cache`，一般刷新即可。

**Q：新增接口返回405，只允许旧方法？**
Python服务不会自动重载。先在原终端Ctrl+C（或IDE停止），重新运行app.py，再刷新页面。
不要重复启动占用同一端口的服务，也不要使用旧进程编号随意终止其他程序。

**Q：登录后马上又跳回登录页？**
会话 24 小时过期；若刚重置过密码，旧会话已失效，需用新密码登录。

**Q：`database is locked`？**
SQLite 单写入者，短时间大量写入时可能出现；程序已设置 5 秒忙等待，重试即可。

**Q：想清空数据重来？**
停止服务后删除 `data/user_management.db`，下次启动会重新建库并生成默认管理员。

**Q：Windows 控制台中文乱码？**
使用 `start.bat`（已设置 `chcp 65001` 与 `PYTHONUTF8=1`），或手动 `chcp 65001`。
